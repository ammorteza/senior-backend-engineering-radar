## What it is

k6 runs programmable load tests, commonly using JavaScript test scripts, and emits request and custom metrics. Its scenarios distinguish user-paced load from fixed arrival-rate demand.

## Why it matters for backend engineers

An API that passes functional tests may fail under concurrency. Selecting the wrong load model can hide overload by letting slow responses reduce the test's arrival rate.

## How it works

Virtual users execute scripted operations. Closed-model scenarios reuse a set of users; arrival-rate executors schedule iterations independently of response completion. Checks record correctness observations, while thresholds determine pass/fail criteria. Sufficient load-generator capacity is essential for the requested rate to be achieved.

## Key concepts

An iteration may contain several HTTP requests. Dropped iterations can indicate inadequate configured users or generator capacity. Tags should have bounded values. Latency metrics describe the measured request stages and must be interpreted alongside scenario behavior.

## Production example

A reports endpoint must sustain a stated submission rate. The test uses an arrival-rate executor, realistic authentication and multiple report sizes. Thresholds cover failure rate and latency; custom checks verify valid response content. Dropped iterations are investigated rather than excluded to make the chart look healthy.

## Trade-offs

Scripts are easy to version and automate. A synthetic generator does not automatically reproduce production data skew, connection behavior or user journeys.

## Failure modes / pitfalls

Using only happy-path payloads, exhausting the generator, testing the wrong environment and treating successful status codes as correct responses invalidate results.

## When to use it

Use k6 for repeatable API capacity tests, regression comparisons and controlled soak scenarios.

## When not to use it

Do not send uncontrolled load to production or use a single short test as a capacity guarantee.

## What a Senior Engineer should know

Choose scenario models, thresholds and checks; monitor the generator and target together.

## What a Staff Engineer should understand

Define representative workloads and safe test environments with explicit acceptance criteria.
